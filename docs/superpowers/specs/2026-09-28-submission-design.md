# SP Training Homework Submission Design

## Repository layout

Create one private repository named `Frido0319/sp_vision_tutorial_27`. Preserve the team repository as read-only `origin` and add the private repository as `submission` with a non-sensitive HTTPS URL.

- Push the completed Lecture 2 and Lecture 3 history to `submission/main`.
- Push the Lecture 4 work based on the official navigation branch to `submission/nav`.
- Never push to `TongjiSuperPower/sp_vision_tutorial_27`.

## Validation before push

Lecture 2 receives a fresh Ubuntu 22.04 build plus its static, model-loading, and AprilTag smoke checks. Lecture 3 receives all provided tests plus the full homework checker. Lecture 4 receives ROS2 Humble build and bounded integration evidence. A remote API check then verifies repository visibility, branch heads, and commit identities.

## Submission boundary

The GitHub push is authorized. The private QQ message is prepared but not sent. It will contain the private repository URL, branch mapping, and an explicit note that the Lecture 2 physical Hikrobot test remains for the student. Student number and legal name are not discoverable from the repository or exported group snapshot, so the final message keeps clearly marked fields for the student to fill if those values are still unavailable.
